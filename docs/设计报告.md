# HyperMedia_Lite 媒体查看器 — 设计方向 & 工程计划报告

> 版本：v1.0 ｜ 日期：2026-11-22
> 目标：在现有 `HyperMedia_Lite` UWP 空白项目上，开发一个集**音频、视频、图片**于一体的本地媒体查看器。
> 报告结构：① 现状分析 → ② Groove 音乐设计思路收集 → ③ 界面设计方向 → ④ 工程计划 → ⑤ 风险与验收 → 附录（资料来源）。

## 1. 项目现状分析

对仓库现有文件的逐一梳理结果：

| 项目 | 现状 |
| --- | --- |
| 项目类型 | UWP（Universal Windows Platform），C# + XAML，`OutputType=AppContainerExe` |
| 目标平台 | `TargetPlatformVersion 10.0.22621.0`（Windows 11 22H2 SDK），最低 `10.0.10240.0`（Windows 10 初版） |
| UI 技术 | `Windows.UI.Xaml`（经典 UWP XAML，非 WinUI 3） |
| 依赖 | 仅 `Microsoft.NETCore.UniversalWindowsPlatform 6.2.14`，无任何第三方控件库 |
| 代码 | `App.xaml.cs` 为标准空白模板（Frame 导航 + Suspending 占位）；`MainPage` 只有一个空 `Grid`，无任何业务代码 |
| 清单 | 仅声明 `internetClient` 能力；**未声明**音乐/图片/视频库、文件打开等能力 |
| 本地化 | `DefaultLanguage=zh-CN`，资源为 `x-generate` |
| 签名 | `AppxPackageSigningEnabled=false`，未签名 |

**结论**：这是一个干净但完全没有功能的起点。好处是没有历史包袱、可自由定架构；代价是媒体能力、文件访问权限、导航框架、主题资源等都需要从零搭建。

## 2. Groove 音乐（Windows 预装）设计思路收集

### 2.1 收集方式与资料说明

- ✅ **直接获取的官方资料**（本次实际抓取成功）：Microsoft Learn 的「Design Windows apps」「Design principles」「Navigation basics」「Materials」「Color」「List/details」等页面，内容见附录。
- ⚠️ **受限来源**：Wikipedia 页面与关键词搜索引擎在本环境无法直连（网络/区域限制），Bing 抓取到的中文结果相关度低。因此下文中关于 **Groove 音乐本身的产品设计特征**，来自对该产品的公开产品知识整理，属于「产品观察」性质，而非本次联网抓到的原文；其设计原则与微软官方 Fluent 指南相互印证。
- 背景事实：Groove Music（前身为 Xbox Music，2015 年随 Windows 10 更名）曾是 Windows 10 内置音乐应用，后被逐步下线（本次 Bing 结果中 Microsoft Q&A（2026-01）亦确认微软已不再单独提供 Groove 下载）。**它的设计遗产——内容驱动、沉浸式播放、极简 chrome——被后续的 Fluent Design 与 Windows 媒体应用广泛继承**，因此对本项目仍有很高的参考价值。

### 2.2 Groove 音乐的核心设计 DNA

**① 内容优先，界面退后（Content-first, chrome recedes）**

- 专辑封面、艺人照片是界面的绝对主角；导航、按钮、边框被压缩到最低限度。
- 页面头部大量使用**全出血（full-bleed）大图 Hero**：封面/艺人图铺满顶部，标题叠加其上，用渐变保证文字可读性。
- 设计信条可概括为：「让用户感觉在浏览音乐，而不是在浏览一个文件管理器」。

**② 封面驱动的强调色（Content-driven accent color）**

- 播放界面会从当前专辑封面**提取主色**，并映射到背景渐变、进度条、高亮控件上，使整个界面「随音乐变色」。
- 这与官方指南一致：Windows 的强调色用于强调重要元素、指示交互状态，且应「适度使用」（[Color in Windows]）。我们可把系统强调色与「媒体封面色」结合：默认跟随系统主题色，沉浸播放页使用媒体取色。

**③ 一个常驻、可大可小的播放控制层**

- 底部**迷你播放条**常驻，显示封面缩略图、曲名、播放/暂停、进度，用户可不离开当前页控制播放。
- 点击展开为**「正在播放（Now Playing）」沉浸页**：大幅封面 + 模糊放大的背景 + 歌词 + 完整传输控制 + 播放队列。
- 支持**画中画 / 精简覆盖（Compact Overlay）**小窗，让播放悬浮在其他应用之上。多媒体查看器应把这个模式同时提供给音频和视频。

**④ 清晰一致的左侧导航 + 搜索入口**

- 汉堡菜单 / 左侧导航 pane 组织「我的音乐、播放列表、专辑、艺人、歌曲、流派、电台」等，层级扁平、命名直白，顶部为搜索框。
- 官方导航指南建议：顶层页面数量多（>5）时用**左侧导航（NavigationView）**；页面数少且文字类别不宜用图标时用顶部导航。对本项目「音乐 / 视频 / 图片 / 收藏 / 播放列表」的结构，左侧 NavigationView 是自然选择（[Navigation basics]）。

**⑤ 卡片化内容浏览 + 列表/详情切换**

- 专辑、歌单以 **GridView 卡片**呈现（方形封面 + 标题 + 副标题）；歌曲以 **ListView 列表**呈现。
- 当选中项需要展示详情时，采用 **列表/详情（List/details）模式**：窄窗口堆叠、宽窗口并排（[List/details]）。图片库尤其适合这种模式——左侧缩略图列表，右侧大图 + 元数据。

**⑥ 沉浸式媒体：模糊、景深与材质**

- Now Playing 背景使用被模糊、放大、压暗的封面图，营造景深；文字与控件浮于其上。
- 依托 Fluent 材质：**Acrylic（亚克力）**用于浮出层、上下文菜单等瞬时表面；**Mica（云母）**用于窗口主背景，随桌面壁纸着色并区分窗口焦点；**Smoke**用于模态遮罩（[Materials]）。注意 UWP 中 AcrylicBrush / Mica 的可用性与 SDK 版本相关，需做降级。

**⑦ 交互细节体现「顺滑」**

- 页面切换、列表筛选使用轻量动画；即时搜索过滤；右键上下文菜单（播放、加入播放列表、删除等）；拖拽整理播放列表。
- 翻页/切歌保持上下文连续，避免「跳转—返回」的 pogo-sticking（[Navigation basics]）。

**⑧ 品牌与排版**

- Groove 品牌为紫粉渐变与声波造型 Logo；界面字体为 Segoe UI，标题字号大、字重轻，留白充足。
- 官方 Windows 11 设计原则可概括为：**Effortless（轻松高效）、Calm（平静克制）、Personal（个性化）、Familiar（熟悉）、Complete + Coherent（完整一致）**（[Design principles]）。这正是 we 要继承的气质。

### 2.3 从 Groove 提炼、可迁移到「音视频图一体化查看器」的设计原则

1. **内容即界面**：缩略图/封面/帧画面是主角，UI 是配角。
2. **一个强调色贯穿全局**：控件、进度、选中态统一取色；沉浸场景允许媒体取色。
3. **一个常驻播放层**：音频和视频共用底部迷你条 + 可展开的全屏播放页 + 画中画。
4. **扁平、可预测的导航**：NavigationView 左导航 + 顶部搜索，层级不超过两层。
5. **自适应的卡片/列表**：宽屏 GridView/并排详情，窄屏堆叠（List/details 模式）。
6. **深色优先、主题可选**：媒体浏览在暗色环境下最舒适，但要完整支持浅色/深色跟随系统。
7. **动效克制、反馈直接**：过渡、悬停、按压反馈要「响应式、直接、符合场景」（[Motion]）。

## 3. 界面设计方向

### 3.1 整体定位

> 做一个「Windows 原生质感」的本地媒体中心：**groove 式沉浸播放 + 文件级浏览效率 + 三种媒体统一体验**，而不是三个割裂的播放器。

设计气质对齐 Windows 11 五项原则：Effortless / Calm / Personal / Familiar / Coherent。

### 3.2 信息架构（建议）

```
NavigationView（左侧，可折叠）
├─ 概览（Overview）        ← 最近添加 / 最近播放 / 随机推荐 Hero
├─ 音乐（Music）
│   ├─ 全部歌曲 / 专辑 / 艺人 / 流派
├─ 视频（Video）
│   └─ 全部视频 / 文件夹
├─ 图片（Photos）
│   └─ 全部图片 / 相册(按文件夹)
├─ 收藏（Favorites）
└─ 播放列表（Playlists）
顶部：全局搜索框 + 视图切换 + 主题/设置
底部：常驻迷你播放条（音频/视频）  ← 全局，跨页面
浮层：Now Playing 沉浸页 / 图片灯箱 / 画中画
```

- 顶层 6 项左右，用 NavigationView 左侧导航；音乐/视频/图片内部用 Pivot 或二级列表，控制在两层内。
- 全局搜索贯穿音乐 / 视频 / 图片；结果按类别分组。

### 3.3 关键页面设计

| 页面 | 布局与交互 |
| --- | --- |
| **概览** | 顶部 Hero：最近媒体大图 + 渐变遮罩 + 主操作按钮（播放全部/幻灯片）。下方横向分组：最近播放、最近添加、图片回忆，各为可横向滚动的卡片行。 |
| **音乐库** | 专辑 GridView（方形封面卡片），歌曲 ListView（标题/艺人/时长/专辑）。右键菜单：播放、下一首播放、加入列表、收藏、查看详情。底部迷你条常驻。 |
| **视频库** | 视频卡片显示首帧缩略图 + 时长角标 + 分辨率。点击打开播放器页；卡片右键「打开所在文件夹」。 |
| **播放器页（音频/视频共用容器）** | 视频：`MediaPlayerElement` 全区域 + 传输控件 + 全屏 + 画中画；音频：大封面 + 从封面取色的模糊背景 + 频谱/歌词占位 + 完整传输控制 + 队列侧栏。两者共用同一套播放状态与迷你条。 |
| **图片库** | 按文件夹分组的 GridView；点击进入灯箱：全屏黑底、居中大图、支持缩放/平移、左右切换、底部缩略图胶片条、右侧元数据面板（尺寸/拍摄时间/EXIF）、幻灯片播放。 |
| **列表/详情** | 宽屏：左侧列表 + 右侧详情并排；窄屏（<641 epx）：堆叠为两页，选择后进入详情；用 `AdaptiveTrigger` + `VisualState` 实现（[List/details]）。 |

### 3.4 视觉系统

- **主题**：默认跟随系统（RequestedTheme），同时提供应用内浅色/深色切换；媒体浏览以深色为主基调。
- **颜色**：中性灰阶打底（背景、表面），系统强调色 + 媒体封面取色作为唯一点缀色，仅用于选中态、进度、主按钮；遵循对比度与色盲可辨识要求（[Color in Windows]）。
- **材质**：主窗口背景用 Mica（若目标版本支持，否则降级为纯色）；浮出菜单/播放页浮层用 Acrylic；模态对话框用 Smoke。
- **排版**：Segoe UI / Segoe UI Variable，标题 28–40px 轻字重，正文 14–16px，留白充足。
- **几何与图标**：圆角卡片与控件（8px 系），Segoe Fluent Icons 图标字体；封面卡片统一圆角与阴影层级。
- **动效**：页面切换淡入 + 轻微位移（~150–200ms）， hover/press 即时反馈，灯箱支持流畅缩放过渡（[Motion]）。
- **响应式**：VisualState + AdaptiveTrigger，断点对齐 320/641 epx 规则；支持桌面、平板、不同 DPI、键盘导航与讲述人。

### 3.5 与「Groove 精髓」的对应关系

| Groove 特征 | 本项目落地方式 |
| --- | --- |
| 封面大图 Hero | 概览页 Hero + 音乐页专辑封面卡片 + 播放页大封面 |
| 封面取色 | `AccentColorService` 提取专辑/视频帧/图片主色，驱动沉浸页 |
| 迷你播放条 + Now Playing + 画中画 | 全局 `PlaybackBar` + `NowPlayingPage` + CompactOverlay |
| 左侧导航 + 搜索 | `NavigationView` + 顶部 `AutoSuggestBox` |
| GridView / 列表详情 | 媒体卡片 GridView + 自适应列表/详情 |
| Acrylic / Fluent 动效 | 材质与过渡动画 |

## 4. 工程计划

### 4.1 技术栈决策

- **保持 UWP + `Windows.UI.Xaml`**，目标版本维持 10.0.22621.0、最低 10.0.10240.0，避免改写现有 `App.xaml.cs` 与项目文件。
- **建议引入 WinUI 2（`Microsoft.UI.Xaml`）NuGet**：在 UWP 中获得 modern `NavigationView`、`AcrylicBrush`、`TeachingTip`、`TabView`、`InfoBar` 等控件，同时保留 UWP 部署模型。注意低版本 SDK（<16299）对部分控件的降级处理。
- 播放内核使用 `Windows.Media.Playback.MediaPlayer` + `MediaPlayerElement`（UWP 原生，覆盖常见音视频格式，省去自研解码）。
- 文件访问使用 `Windows.Storage` API（选择器 + KnownFolders/库 + 元数据属性 `MusicProperties`/`VideoProperties`/`ImageProperties`）。

### 4.2 架构设计（MVVM + 服务层）

```
HyperMedia_Lite/
├─ Models/            MediaItem(基类), AudioItem, VideoItem, PhotoItem, Playlist
├─ ViewModels/        MainVM, LibraryVM, MusicVM, VideoVM, PhotoVM,
│                     PlayerVM, PlaylistVM, SettingsVM
├─ Views/             MainPage, OverviewPage, MusicPage, VideoPage, PhotoPage,
│                     PlayerPage, NowPlayingPage, PhotoViewerPage, SettingsPage
├─ Services/          LibraryScanService, MetadataService, PlaybackService,
│                     AccentColorService, PlaylistService, SettingsService,
│                     NavigationService, SearchService
├─ Controls/          PlaybackBar, MediaCard, HeroBanner, PhotoLightbox
├─ Converters/        TimeSpan, BoolToVisibility, CoverFallback ...
└─ Helpers/           RelayCommand, BindableBase, ThemeHelper, DeepLinkHelper
```

- **BindableBase + RelayCommand** 实现 MVVM，`ObservableCollection<MediaItem>` 绑定列表；列表使用 `ItemsControl`/`ListView` 的 UI 虚拟化 + 增量加载支撑大批量媒体。
- **PlaybackService** 单例封装 MediaPlayer，向各 VM 广播播放状态；`SystemMediaTransportControls` 接入系统媒体键与锁屏控制。
- **LibraryScanService** 基于 `StorageFolder.CreateFileQueryWithOptions` + 后台增量扫描，结果缓存到 `ApplicationData.Current.LocalFolder` 的索引文件，避免每次冷启动全量扫描。
- **AccentColorService** 从封面/首帧/图片提取主色（可先用简单的像素量化，后续可换更优算法），输出 SolidColorBrush 给沉浸页。

### 4.3 分阶段交付（里程碑）

| 阶段 | 周期（参考） | 交付内容 | Exit Criteria |
| --- | --- | --- | --- |
| **P0 基础框架** | 第 1–2 周 | 引入 WinUI 2；建立 MVVM 骨架；NavigationView + Frame 导航；主题资源与 Mica/Acrylic；清单能力声明（musicLibrary/picturesLibrary/videosLibrary + fileOpenPicker） | 各页面可空壳切换，主题切换生效，可申请权限读取库 |
| **P1 媒体库 & 播放核心** | 第 3–5 周 | LibraryScan + Metadata；音乐/视频/图片页与 GridView/ListView；MediaPlayer 播放、播放/暂停/进度/音量；全局迷你播放条；图片灯箱基础（缩放/切换） | 能扫描本地媒体并播放音频、视频、浏览图片，迷你条跨页常驻 |
| **P2 沉浸体验** | 第 6–8 周 | Now Playing 沉浸页 + 封面取色；画中画 Compact Overlay；播放列表/收藏；搜索与排序；列表/详情自适应；右键菜单 | 三个媒体的核心体验闭环，交互与设计规范一致 |
| **P3 打磨与扩展** | 第 9–11 周 | 幻灯片、歌词/频谱占位、键盘快捷键与小键盘媒体键、动效打磨、无障碍与本地化、后台播放与系统媒体集成 | 通过验收清单，可签名打包 |
| **P4 可选增强** | 后续 | 跨设备同步/云、智能歌单、DLNA/投屏、EXIF 编辑、AI 分类 | 按需求排期 |

### 4.4 关键实现要点（UWP 特定）

- **清单能力**：在 `Package.appxmanifest` 增加 `musicLibrary`、`picturesLibrary`、`videosLibrary`；任意位置文件用 `FileOpenPicker` + `FutureAccessList` 记住访问权限；关联文件类型打开用 `FileTypeAssociation` 声明。
- **生命周期**：完善 `OnSuspending` 保存播放位置、队列与导航状态；`OnLaunched` 恢复；处理 `EnteredBackground/LeavingBackground` 与后台播放。
- **媒体播放**：`MediaPlayerElement.SetMediaPlayer`；视频全屏与 `IsCompactOverlayEnabled`；系统媒体控制 `SystemMediaTransportControls` 同步封面（缩略图）与元数据。
- **性能**：列表虚拟化 + `IncrementalLoadingCollection`；缩略图用 `StorageItemThumbnail` 缓存到内存/磁盘；取色在后台线程进行并缓存。
- **自适应**：`AdaptiveTrigger.MinWindowWidth` 在 641 epx 切换堆叠/并排；MinWindowWidth 320 起保证可用。
- **兼容性**：AcrylicBrush/Mica/部分 WinUI 2 控件的 API 版本门槛，用 `ApiInformation.IsTypePresent` 做条件编译与降级。

### 4.5 风险与对策

| 风险 | 对策 |
| --- | --- |
| UWP 平台处于维护期，新 API 有限 | 坚守 UWP 降低迁移成本；把 WinUI 2 作为过渡，核心逻辑与 UI 解耦以便未来迁 WinUI 3 |
| 文件权限受限 / 用户拒绝库访问 | 以 FileOpenPicker 为主入口，FutureAccessList 持久化；提供清晰的隐私说明 |
| 大媒体库导致启动慢、内存高 | 索引缓存 + 增量加载 + 缩略图缓存 + 虚拟化 |
| 编解码格式兼容（MKV/FLAC 等） | 依赖系统 MediaPlayer 与可选编解码器扩展；不支持格式给出明确提示 |
| 封面取色性能与观感不稳定 | 后台计算 + 缓存 + 回退到系统强调色；限定饱和度/亮度区间 |
| 低版本系统（10240）特性缺失 | ApiInformation 检测 + 降级主题/材质；最低版本可视情况上调到 16299 以简化（需权衡用户覆盖） |
| 未签名无法安装 | 开发期用开发者模式侧载；发布前配置签名与 Store 打包 |

### 4.6 测试与验收

- 功能：扫描/索引正确性、三类媒体播放与切换、搜索/排序/收藏/播放列表、灯箱缩放、画中画、系统媒体键。
- 兼容性：Windows 10 与 11、x86/x64/ARM64、桌面与平板、高 DPI、浅色/深色主题。
- 非功能：冷启动时间、万级条目列表滚动帧率、内存占用、键盘可达性、讲述人/高对比度、本地化（zh-CN 优先）。
- 验收以第 4.3 节各阶段 Exit Criteria 为准。

---

## 5. 结论

Groove 音乐最值得借鉴的不是某个具体控件，而是**「让内容成为界面、让控制随时可得、让界面安静退后」**的产品哲学。结合微软官方 Fluent Design 的导航、材质、颜色、动效与自适应指南，本项目应采取：

- **统一架构**：三类媒体共用一个 NavigationView 外壳与一个全局播放层；
- **沉浸体验**：封面/Hero 驱动的视觉、封面取色、Now Playing、画中画；
- **原生质感**：Mica/Acrylic、Segoe 排版、克制动效、深浅主题；
- **稳健工程**：MVVM + 服务层、增量扫描与缓存、生命周期与权限、分阶段交付。

按 P0–P3 约 11 周可交付一个完整可用的本地音视频图查看器，P4 作为后续增强。
