# HyperMedia_Lite 未来规划

> 记录日期：2026-11-25
> 背景：项目已完成媒体库 / 播放 / 图片灯箱与编辑 / 歌词 / 字幕 / 响应式 / 15063 兼容主体。
> 当前最低版本：csproj 16299（编译期），manifest 15063（部署期），与参考文章方法一致。

## 一、现状盘点（已具备的能力）

- 音频：播放队列、播放顺序、进度 / 音量、封面取色、SMTC、桌面歌词、内嵌 / 在线歌词 + 逐字高亮。
- 视频：应用内播放（现代路径 MediaPlayerElement / 10240+ MediaElement 后端）、内嵌字幕轨选择、外挂 SRT/VTT/ASS 自绘字幕。
- 图片：灯箱（缩放 / 平移 / 旋转 / 翻转 / 幻灯片）、EXIF 信息、编辑（裁剪 / 调色 / 滤镜 / 撤销重做）。
- 工程：MVVM、RelayCommand、FutureAccessList 持久化、LRU 缩略图缓存、ApiInformation 守卫、同步启动日志。

换句话说：**「看完、听好、能改」已经闭环**，下一步的重点应从「补齐基础能力」转向「打通输出与场景」和「规模化 / 打磨」。

## 三、重点方向详述

### 3.1 图片打印（已实现）

**目标**：在灯箱 / 图片页点击「打印」，把当前图片按纸张排版输出。

**实现落点**：`Services/PrintService.cs`（`PrintManager` + `PrintDocument` 的 `Paginate` / `GetPreviewPage` / `AddPages` 事件）+ 灯箱顶部工具栏打印按钮。按 `PrintPageDescription.ImageableRect` 计算边距，`Image Stretch="Uniform"` 居中适应页面。

> 当前支持打印正在查看的单张图片；多图批量打印留作后续扩展。

**技术路线**：
- `PrintManager.GetForCurrentView().PrintTaskRequested` 注册打印任务；
- `PrintDocument` + `PrintDocument.PrintPage` 事件里用 `e.DrawPreview` / `DrawPage` 绘制 `BitmapImage`；
- 排版：根据 `e.PageBounds.Width / Height` 与图片比例计算居中缩放，尊重 DPI；
- 多图：每个 `PrintPage` 绘制一张，用 `e.HasMorePages` 翻页；
- 选项：纸张尺寸 / 方向由系统打印面板提供，应用只处理「适合页面」与边距；
- 10240 / 15063：`Windows.Graphics.Printing` 在 10240 即可用，无条件可用。

**UI 落点**：图片灯箱工具栏「更多」菜单加「打印」；图片页右键菜单也加一项。

**风险 / 注意**：
- 打印预览需要提前解码原图，大图注意内存；
- 某些打印机对 UWP 的 PrintTicket 支持有限，提供「缩放以适应页面」兜底；
- 打印任务需在页面可见时注册，离开页面取消订阅。

### 3.2 云歌词（聚合 + 自定义源）

**目标**：把现有「网易云 / QQ 双源」升级为可扩展的歌词云，提升命中率与可控性。

**现状**：`Services/OnlineLyrics.cs` 已实现两源搜索、候选打分（`LyricMatcher`）、strict 优先并发探测、6 条可用即止、本地缓存。

**演进步骤**：
1. **多源适配层**：抽象 `ILyricSource { SearchAsync, FetchAsync }`，把网易云 / QQ 迁入；再新增酷狗 / 搜狗 / 第三方 LRC API。
2. **源开关与排序**：设置页勾选启用的源与优先级；失败自动降级下一源。
3. **自定义源模板**：用户填 API URL 模板（如 `{title}` / `{artist}` 占位），解析返回 JSON / 纯 LRC，便于自建歌词服务。
4. **本地缓存增强**：缓存记录来源 / 命中时间 / 用户选择；支持「全部歌词」（已有）与「重新匹配」（已有 ChangeLyrics）。
5. **翻译（可选）**：对外文歌词，接入翻译 API 或离线词典，作为副行显示；桌面歌词也可显示译文。

**注意**：
- 所有网络请求用 `Windows.Web.Http`（已用），15063 可用；
- 自定义源要注意隐私提示（URL / 元数据是否外发）；
- 第三方 API 可能不稳定，超时与重试要短，避免阻塞 UI。

### 3.5 本地歌词 / 字幕自动匹配（建议优先）

**问题**：选择面板已支持「使用本地歌词…」，但每次都要手动挑文件；多数用户其实把 `.lrc` 和音乐放同一目录。

**方案**：
- 播放歌曲时，按 `Path.GetDirectoryName` + `Path.GetFileNameWithoutExtension` 查找同名 `.lrc / .krc / .qrc`；
- 再查同目录的 `Lyrics` / `lyrics` 子目录；文件名也兼容「艺人 - 歌名」两种写法；
- 视频同理查同名 `.srt / .ass / .vtt`；
- 命中后直接解析显示（本地优先，不走网络）；未命中再进入在线搜索 → 选择面板。

**理由**：纯文件 I/O，无新 API，15063 完全可用；和刚建好的选择面板互补，把歌词从「每次手动找」变成「开箱即用」。

**注意**：只查已知目录，不做全盘递归；读取失败静默降级；避免与「已记住的歌词选择」冲突——用户显式选择优先于自动匹配。

### 3.3 全局搜索页（P1-4）

- 单个 `SearchPage`，输入即过滤；结果按「歌曲 / 专辑 / 视频 / 图片 / 播放列表」分组；
- 点击结果直接播放 / 打开，保持导航上下文；
- 复用现有 `LibraryService` 的集合，不重复扫描。

### 3.4 画中画（P1-5）

- 14393+ 用 `ApplicationViewSwitcher.TryShowAsStandaloneAsync` 弹出紧凑窗口；
- 15063 可用，但要 `ApiInformation` 守卫；10240 回退到系统播放器；
- 与迷你播放条 / 全屏页共用同一个 `PlaybackService`。

## 四、推荐执行顺序

1. **P0 收尾**：先确认 Release 生成 / 打包 / 15063 实机运行稳定（当前所有兼容工作都为此服务）。
2. **图片打印 + 分享**：输出闭环，实现简单、感知强。
3. **云歌词聚合**：在已有基础上扩展，风险低。
4. **全局搜索 + 后台播放**：效率与场景闭环。
5. **画中画 / 幻灯片增强**：锦上添花。
6. **工程化**：单元测试 → 拆分巨型文件 → 本地化 → 无障碍。

## 五、原则

- 任何新 API 先确认 15063 可用性，不可用则 `ApiInformation` 守卫 + 降级。
- 网络功能一律可关闭、可超时、可缓存，不阻塞 UI。
- UI 改动沿用四档响应式与现有设计令牌，保持 Groove 风格一致。
- 每完成一项更新 `ROADMAP.md` 状态。

## 六、发散：参考其它播放器的候选功能

> 参考：AIMP 5.40（智能播放列表 / 书签 / 播放统计 / 自动评分 / 20 段均衡器 / 交叉淡入淡出 / 定时任务 / 网络电台 / 标签批量编辑 / CUE / ReplayGain / BPM / Last.fm scrobbler / 多输出设备）、
> VLC（字幕同步偏移 / 视频滤镜 / 章节 / A-B 循环 / 截图 / 全格式字幕）、MusicBee / foobar2000（规则式媒体库 / 批量标签 / 转换器 / 占位文件）。
> 下面只列**本项目尚未覆盖**且 UWP 15063 可落地的方向，按「价值 / 成本」标注。

### 6.1 媒体库与整理（高价值，中低成本）

| 方向 | 说明 | 成本 |
| --- | --- | --- |
| **智能播放列表** | 规则式（流派 / 年份 / 评分 / 最近播放 / 播放次数）自动生成，替代纯手工路径列表 | 中 |
| **播放统计与自动评分** | 每曲播放次数 / 最后播放 / 跳过次数；按听歌频率自动算星级（AIMP 思路） | 低-中 |
| **五星评分** | 用 `MusicProperties.Rating` 读写，和现有收藏并存 | 低 |
| **书签 / 续播位置** | 长音频 / 视频记录播放位置，下次从书签续播 | 中 |

| **批量标签编辑增强** | 多选文件套用同一艺人 / 专辑、自动编号、按文件名回填（已有单文件编辑器，可扩展） | 中 |

### 6.2 听感与播放控制（中高价值，成本高）

| 方向 | 说明 | 成本 |
| --- | --- | --- |
| **淡入淡出 / 交叉淡入** | 切歌时音量渐变，避免突兀；可用 `DispatcherTimer` 做音量斜坡 | 中 |
| **无缝播放 (Gapless)** | 用 `MediaPlaybackList` 替代手动 `MediaPlayer.Source` 切换（需重构队列） | 高 |
| **10 段均衡器** | UWP 没有轻量内置 EQ，需用 `AudioGraph` + 自定义 DSP，风险高 | 高 |
| **音量归一化 / ReplayGain** | 读取标签或离线分析，统一响度 | 高 |
| **睡眠定时 / 定时任务** | N 分钟后暂停 / 播完当前列表关机；AIMP Simple Scheduler 思路 | 中 |
| **网络电台** | 解析 M3U / PLS，HTTP 音频流播放 + 录制 | 中 |

### 6.3 视频增强（中价值，中低成本）

| 方向 | 说明 | 成本 |
| --- | --- | --- |
| **字幕时间偏移** | 字幕整体提前 / 延后几百毫秒，VLC 的招牌功能；对外挂字幕尤其有用 | 低 |
| **章节导航** | `TimedMetadataTracks` 里已经有 `Chapter` 轨（日志里见过），做成章节列表 | 中 |
| **A-B 区间循环** | 记住 A/B 两个时间点，循环播放片段 | 中 |
| **视频截图** | 播放中抓帧保存到图片库 | 中 |
| **细粒度倍速** | 从按钮循环改为 0.25×–3× 滑条 / 预设 | 低 |

### 6.4 图片增强（中价值，低成本）

| 方向 | 说明 | 成本 |
| --- | --- | --- |
| **设为壁纸** | `UserProfilePersonalizationSettings.TrySetWallpaperImageAsync`，15063 可用 | 低 |
| **多选批量操作** | 批量旋转 / 复制 / 导出 / 设为轮播（多选框架已有） | 低-中 |
| **EXIF 地图定位** | 有 GPS 的图片在 `MapControl` 上显示 | 中 |
| **OCR 文字识别** | `Windows.Media.Ocr` 10240 起可用，图片文字可复制 / 搜索 | 中 |

### 6.5 系统集成（中价值，低成本）

| 方向 | 说明 | 成本 |
| --- | --- | --- |
| **拖拽导入** | 从资源管理器拖文件 / 文件夹到媒体库窗口 | 低 |
| **分享目标 / 分享契约** | 把当前歌曲 / 图片 / 视频分享给其它应用（已有打印，分享未做） | 低 |
| **URI 激活 `hypermedia://`** | 从浏览器 / 快捷方式唤起并播放指定文件 | 中 |
| **可配置快捷键** | 现有 Esc/R/F/I/空格，扩展为设置页可改的全局 / 局部热键 | 中 |

### 6.6 排在最后的（价值低或风险高）

- **Last.fm / ListenBrainz scrobbler**：需要 API key 与用户授权，隐私敏感。
- **音频格式转换**：UWP 原生转码能力有限，外部编码器集成复杂。
- **CUE 分轨**：解析不难，但虚拟轨与元数据映射繁琐，用户量小。
- **播客 / 云服务**：需要账号体系，超出本地播放器定位。

### 6.7 建议的下一轮优先级

1. **字幕时间偏移 + 五星评分 + 播放统计**（成本低、体感直接）
2. **睡眠定时 + 设为壁纸 + 拖拽导入**（都是小功能，堆起来很实用）
3. **智能播放列表 + 书签续播**（开始触及" organise 我的音乐"核心）
4. **章节导航 / A-B 循环 / 截图**（视频深度用户）
5. **淡入淡出 / 均衡器**（要不要做取决于是否愿意重构播放核心）

> 原则不变：先确认 API 在 15063 可用；任何需要重构 `PlaybackService` 的方向（无缝、EQ、AudioGraph）单独评估，不要和 UI 小功能混在一起做。

## 七、下一轮三选一的评估（2026-11-28）

### 7.1 主页（Dashboard）—— 推荐先做

**价值高、风险低**。目前启动直接进「我的音乐」，没有聚合入口。而刚加入的播放统计（播放次数 / 最后播放 / 评分）正好可以喂给主页：

- 继续播放 / 最近播放（按 `LastPlayed` 排序）
- 常听（按 `PlayCount` 排序）
- 收藏、最近添加、播放列表、统计摘要入口

纯 UI + ViewModel 聚合，不碰播放核心；导航加一项 `Home` 并设为默认即可。

### 7.2 视频填充 / 画面比例 —— 值得顺手做

**成本低、体感明显**。`MediaPlayerElement.Stretch` 原生支持 `Uniform`（适应，有黑边）/ `UniformToFill`（填充，裁切）/ `Fill`（拉伸）/ `None`（原始尺寸）；再配一个缩放/平移变换就能做"放大到某区域"。做成播放菜单里的「画面模式」四项即可，不动解码管线。

### 7.3 视频滤镜 —— 建议暂缓

UWP 的 `MediaPlayer.AddVideoEffect` 需要实现 `IVideoEffectDefinition` 的自定义 WinRT 组件；系统自带的 `VideoTransformEffectDefinition` 只能做旋转 / 裁切 / 镜像 / 缩放，**没有调色能力**。用半透明色块盖一层只能算"假滤镜"，不值得。除非愿意引入自定义效果组件，否则投入产出比低。

### 7.4 图片编辑加强 —— 可做但要收窄

`ImageEditService` 已有：亮度 / 对比度 / 饱和度、7 种滤镜、白平衡、模糊、锐化、暗角、裁剪、旋转、翻转、缩放保存。真正缺的是**文字水印 / 相框 / 批处理**，其中文字水印需要把文本栅格化进像素缓冲（可做，但比调参数复杂一档）。

**建议顺序**：主页 → 视频画面模式 → 图片文字水印 / 批处理；视频调色滤镜暂缓。
