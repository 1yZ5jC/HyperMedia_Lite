# 10240 兼容性与两手准备

> 项目声明的最低版本：`10.0.10240.0`（Windows 10 1507，`csproj` 与 `Package.appxmanifest` 一致）。

## 1. 阻塞项审计

| API / 控件 | 引入版本 | 项目使用位置 | 10240 后果 | 当前处理 |
| --- | --- | --- | --- | --- |
| `MediaPlayerElement` | 14393 (contract v2) | 原 `MainPage.xaml` 直接声明 | XAML 解析失败，页面无法加载 | **已移除 XAML 声明**，改为 `VideoHost` 占位，代码中按 `UwpCompat.HasMediaPlayerElement` 动态创建 |
| `MediaPlayer.PlaybackSession` / `MediaPlaybackSession` | 14393 | `PlaybackService` 状态/进度 | 构造即抛异常，播放条全部失效 | **已做双路径**：10240 走 `MediaPlayer.CurrentState/Position/NaturalDuration/CanSeek` + `DispatcherTimer` 轮询 |
| `VisualState.Setters` / `AdaptiveTrigger` | 10240 | 响应式布局 | 无 | 可直接使用 |
| `BitmapImage.DecodePixelType` | 10240 | 图片降采样 | 无 | 可直接使用 |
| `QueryOptions.FolderDepth` / `CommonFileQuery.DefaultQuery` | 10240 | 递归扫描 | 无 | 可直接使用 |
| `FolderPicker.PickSingleFolderAsync` | 10240 | 导入文件夹 | 无 | 可直接使用 |
| `BitmapDecoder.GetPixelDataAsync` / EXIF | 10240 | 编辑器 | 无 | 可直接使用 |
| `ContentDialog.CloseButtonText` | 14393 | 旧设置对话框 | 抛异常 | 已改为独立 `SettingsPage`，不再使用 |

**结论**：真正阻塞 10240 的只有 `MediaPlayerElement` 与 `PlaybackSession` 两项，均已通过运行时分支化解。

## 2. 两手准备

### 方案 A：保持 10240（当前默认，已实现）

- 由 `Helpers/UwpCompat.cs` 的 `HasModernPlayback` / `HasMediaPlayerElement` 做运行时判定；
- 10240 行为：
  - 音频：完整可用（播放/暂停、进度、音量、播放顺序、后台事件均走旧 API）；
  - 视频：**仍可应用内播放**。`MainPage.SetupVideoSurface` 创建经典 `MediaElement`（10240 原生控件），通过 `MediaElementVideoBackend`（`Services/LegacyVideoBackend.cs`）接入 `PlaybackService`，使用 `SetSource(stream, contentType)` + `Play/Pause/Stop/Position/Volume` 与 `CurrentStateChanged/MediaEnded` 事件，进度用 `DispatcherTimer` 轮询；
  - 仅当 `MediaElement` 创建失败时才兜底调用 `Launcher.LaunchFileAsync` 交系统播放器；
  - 图片、文件夹导入、编辑器、主题、响应式布局：全部可用；
- 设置页「兼容性」分区会显示当前生效的模式。

### 方案 B：提升最低版本到 14393（需要时切换）

若后续决定放弃 1507 用户、简化维护：

1. `HyperMedia_Lite.csproj`：`<TargetPlatformMinVersion>10.0.14393.0</TargetPlatformMinVersion>`
2. `Package.appxmanifest`：`<TargetDeviceFamily ... MinVersion="10.0.14393.0" .../>`
3. 可将 `PlaybackService` 的 `_useLegacyPlayback` 分支、`MainPage.SetupVideoSurface` 的回退 UI 和 `UwpCompat.HasModernPlayback` 判定移除，统一使用 `MediaPlayerElement` + `PlaybackSession`。

切换后即可删除兼容代码，减少运行时分支。

## 3. 验证建议

- 在 Windows 10 1507 设备/镜像上部署，重点验证：启动不崩溃、音频可播放、进度条走动、视频跳转系统播放器、图片灯箱与编辑器可用。
- 在 Win11 22H2 上验证现代路径不受影响（应用内视频、播放会话事件）。
